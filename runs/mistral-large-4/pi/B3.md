All green — be: 11/11 tests + typecheck clean; web: tests, typecheck, and build all pass.

## What changed

**`be`** — exposes resolve via a new endpoint:
- `src/store.ts`: added `findIncident` and `resolveIncident` (sets `status: "resolved"`, stamps `endedAt` with now).
- `src/routes/incidents.ts`: added `POST /api/homes/:homeId/incidents/:incidentId/resolve`, following the existing zod/`safeParse` conventions → `400 invalid_params`, `404 home_not_found` / `incident_not_found`, `409 already_resolved`, and `{ incident }` on success.
- Fixed a latent bug: the route parsed the filter as `state` while the README and web both send `status`, so `?status=open` was silently ignored. Renamed to `status` so the open-only list is actually open-only.
- `tests/incidents.test.ts`: new tests (same `withServer`/HTTP style as `homes.test.ts`) covering resolve, the open list and badge count dropping afterwards, and the 409/404 paths. README endpoint table updated.

**`web`** — resolve from the dashboard, no reload:
- `src/api.ts`: added a `post` helper and `resolveIncident(homeId, incidentId)` (api.ts remains the only module that knows the backend).
- `src/components/IncidentList.tsx`: each open incident gets a **Resolve** button (disabled with "Resolving…" while in flight, error line on failure). On success the incident is removed from the open list in local state.
- `src/App.tsx`: passes `onResolved` which re-fetches homes, so the per-home open-incident badge in `HomeList` updates too — all without a page reload.
- `src/styles.css`: button styles built from the existing custom properties; incident row is now a 4-column grid and stays fine in the single-column mobile layout.
