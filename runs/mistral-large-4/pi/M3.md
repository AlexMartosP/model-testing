## Summary

**Checkout's error rate jumped from ~0.2% to 4%+ starting at 08:00 UTC today (2026-11-01)**, with p99 latency rising ~4.5x (248ms → 1105ms). It's been elevated for 3 hourly buckets (4.1%, 4.6%, 4.4%).

## Root cause

**Deploy `d-1049` (commit `c7e02a9`, by priya@example.com, deployed 07:41 UTC)** — the deploy notes say: *"Turns on the checkout_tax_v2 rounding path for all regions."* The timing lines up exactly: the deploy finished at ~07:45 and the 08:00 bucket is the first one showing the spike.

Supporting evidence:
- A later deploy, `d-1050` (commit `41b9de7`, 07:52), **failed at build time** (type error in `tax.ts`) and never reached production — so it's not the cause.
- The issue is isolated to checkout: **billing** (0.1–0.2%) and **notifications** (0.4–0.5%) are both at their normal baseline.
- In this repo, the related rounding logic lives in `pricing/pricing.ts` — commit `fc6dbfc` switched `applyDiscount` from `Math.round` to `Math.ceil`, which is exactly the kind of "rounding path" change that would alter tax calculations and likely cause downstream validation failures (e.g., totals no longer matching expected cent values → 4xx/5xx responses).
