## The cross-source claim, and why it is our fixture's fault

It went beyond the MCP data, running nine `bash` calls through the workspace — `git log`,
`git show c7e02a9`, `cat pricing/pricing.ts`, `git show fc6dbfc`, plus sweeps of `tickets/`,
`inbox/` and `be/` — and reported:

> In this repo, the related rounding logic lives in `pricing/pricing.ts` — commit `fc6dbfc`
> switched `applyDiscount` from `Math.round` to `Math.ceil`

Checked: `fc6dbfc` is real, and that is exactly the change it makes. Nothing invented.

But **there is no actual link** between the fictional deploy tracker's `checkout_tax_v2` note and
the `pricing/` history fixture. They are two unrelated fixtures that both happen to be about
rounding — one built for M1/M3, the other for S1. The model found a pattern this repo
accidentally created.

Not a deduction. The commit and its contents are real, the inference is partly hedged ("the kind
of… change that would", "likely cause"), and it is offered as supporting evidence while the root
cause is correctly derived from the MCP data alone. Using every source available is the right
instinct.

**The fixture should change, not the score.** Two unrelated rounding bugs in one sandbox invite a
false connection, and the next model may state it less carefully.
