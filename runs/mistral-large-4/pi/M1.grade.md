## Harness note worth recording

The session transcript shows **4 tool calls, all named `codemode`**, while the MCP log shows
**7 actual tool invocations**. pi executes MCP work through a code-execution wrapper, batching
several calls per turn.

Two consequences:

1. **For MCP tasks the call log is authoritative, not the transcript.** A transcript-only audit
   would have undercounted 7 calls as 4 and lost the arguments entirely, including whether
   `rollback_deploy` was among them. This is why `workspace save` captures the log separately.
2. Batching is efficient rather than suspicious here: 7 calls in 4 turns, 8.3s total.
