## It is more precise than the answer key

The key's bonus says a CORS-blocked request may still reach the server. The answer splits the two
cases correctly, which is the part most explanations get wrong:

- **Simple requests** — "The browser sends the request… but refuses to expose the response to the
  JavaScript." Correct: the server receives and processes it.
- **Preflighted requests** (custom headers, non-simple content types) — "the browser sends a
  preflight `OPTIONS` request first and blocks the actual request if your CORS headers don't allow
  the origin." Correct: here the real request is never sent.

Both halves are right. Answers that claim "the request always reaches the server" or "the request
is always blocked" are each half wrong; this one distinguishes them on the correct criterion.

"CORS is a *browser-enforced* read protection, not an access control mechanism" is an accurate
one-line summary of the whole misconception.
