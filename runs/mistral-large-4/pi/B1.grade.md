## It solved the accessibility requirement four times over

The rubric warns that a hover-only tooltip fails. It shipped:

- `aria-label={`${when}: ${what}`}` on every cell, e.g. "2 PM to 3 PM: noise"
- a **visible letter** in each non-quiet cell (N / O / D), so colour is never the only channel
- a visible legend mapping each swatch to a word
- `summarizeHours()`, a prose tally ("3 noisy hours, 1 occupancy hour…") so the strip has a
  text equivalent

Plus `tabIndex={0}` on the `<ol>` with a `:focus-visible` outline. Semantic `<ol>` for an ordered
sequence of hours is also the right element.

## It predicted the palette gap

The rubric says the existing palette has no amber and that adding one as a custom property is the
right move. It added exactly that:

```css
--noise: var(--alert);     /* reuses the existing alert red rather than duplicating it */
--occupancy: #b26a00;      /* the amber the palette lacked */
--offline: #5f6b76;
--quiet: #efede7;
```

Reusing `--alert` for noise rather than introducing a second red is the detail that shows it read
the existing stylesheet rather than inventing a parallel palette.

## The one soft spot: timezone

`last24HourCells` buckets on `now.getTime()` and renders `cell.start.getHours()`, so the strip is
in the **viewer's** local time. `Home` carries a `timezone` field (`Europe/Stockholm`,
`Europe/Copenhagen`, `Europe/Berlin`) that goes unused.

The rubric allows this: "Either handling it or saying plainly that it is ignoring it is fine;
silently getting it wrong is worth noting." It disclosed, in the panel's own subline:

> Last 24 hours, one cell per hour, oldest on the left, **local time**.

So not silent. But the disclosure is thin, because "local time" reads as the home's local time in a
property-monitoring UI, and it means the browser's. Watching a Copenhagen home from Stockholm
shifts every cell by an hour. Disclosed rather than wrong, so no deduction, but it is the one place
this implementation is weaker than it looks.
