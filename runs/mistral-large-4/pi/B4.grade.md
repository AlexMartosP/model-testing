## It did the thing that separates a 3

The rubric's 3 condition is noticing *why* this shipped, not just what broke:

> A 3 also notices that zod silently drops unknown keys, which is what let this ship, and says so,
> or tightens the schema with `.strict()`.

It did all three available versions of that:

```ts
// Strict on purpose: a misspelled or renamed query param must fail loudly (400) instead of
// being silently dropped, which once made this endpoint ignore `?status=open` entirely.
const incidentQuery = z.strictObject({
  status: z.enum(["open", "resolved"]).optional(),
});
```

Comment explaining the mechanism, `z.strictObject()` to enforce it, **and** a third test asserting
the old wrong name now 400s:

```ts
// `state` was the old, wrong param name; it must 400, not silently return everything.
const { status, body } = await get(`${base}/api/homes/h-01/incidents?state=open`);
assert.equal(status, 400);
```

That last test is the detail worth calling out. The rubric asks for a regression test for *this*
bug; this is a regression test for the *class* of bug. Any future mistyped parameter on this
endpoint now fails loudly instead of quietly returning everything.

## Regression tests

Three added, suite 6 → 9, all passing, typecheck clean:

- `?status=open` returns exactly `["i-1001", "i-1003"]`, and every row is `status === "open"`

Exact id assertions rather than counts, so a future off-by-one can't slip through.
