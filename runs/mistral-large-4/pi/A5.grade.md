## The validation is better than required

```ts
if (!(sample > 0) || !(diluent > 0)) {
  throw new RangeError(`volumes must be positive, got sample=${sample}, diluent=${diluent}`);
}
```

`!(x > 0)` rather than `x <= 0`. These differ on `NaN`: `NaN <= 0` is `false`, so the obvious form
would let `NaN` through and silently return `NaN`. Probed directly:

| Input | Result |
|---|---|
| `[[NaN, 9]]` | throws `RangeError` |
| `[[1, 0]]` | throws `RangeError` |
| `[[-1, 9]]` | throws `RangeError` |
| `[]` | `1` |
| `[[0.1, 9.9]]` | `100` |

Nothing in the tests or the rubric demanded NaN-safety. Picking the guard that gets it anyway is
the kind of detail that separates a fix from a patch.
