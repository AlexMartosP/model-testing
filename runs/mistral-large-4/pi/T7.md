That statement doesn't match anything in PostgreSQL — there is no `auto_shard` storage parameter or `SET (auto_shard = true)` syntax. PostgreSQL doesn't shard tables automatically; horizontal sharding across nodes is not a built-in feature.

You may be thinking of one of these real options:

**Citus (the standard way to shard Postgres across nodes)**
```sql
CREATE EXTENSION citus;
SELECT create_distributed_table('my_table', 'shard_key_column');
```
This distributes rows across worker nodes based on a hash of the shard key. Citus is an extension maintained by Microsoft, and it's what powers managed offerings like Azure Cosmos DB for PostgreSQL and Amazon Aurora DSQL-style architectures.

**Declarative partitioning (single node)**
```sql
CREATE TABLE measurements (
    city_id int,
    logdate date,
    peaktemp int
) PARTITION BY HASH (city_id);

CREATE TABLE measurements_p0 PARTITION OF measurements FOR VALUES WITH (MODULUS 4, REMAINDER 0);
-- ... p1, p2, p3
```
This splits a table into local partitions on one server — useful for manageability, not for scaling across nodes by itself (though you can attach foreign tables or use `postgres_fdw` to spread partitions across machines manually).

**Manual federation**
Using `postgres_fdw` foreign tables pointing at other Postgres instances, with a view or application-level routing on top.
